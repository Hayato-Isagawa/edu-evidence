# 0033. `lastVerified` は「一次ソースとの最終照合日」である

- 状態: 採用
- 日付: 2026-08-05
- 関連 PR: #(本 ADR と同一 PR で確定)

## 背景

`lastVerified` の意味が、リポジトリ内の 4 箇所で食い違っていた。

| 出典 | 書かれていた意味 |
|---|---|
| `docs/CONTEXT.md` | 一次ソースとの最終照合日 |
| `docs/source-sync-protocol.md` | 値の更新が無くても `lastVerified` 単独で rolling 更新する |
| `scripts/check-stale.ts` | 「変更がなければ `lastVerified` を今日の日付に更新」 |
| **`docs/CONTENT_GUIDELINES.md`** | **実質的な内容更新をした場合に更新。軽微な修正では更新しない** |

3 対 1 で「照合日」だが、**執筆時に最も読まれるのは CONTENT_GUIDELINES** であり、そこだけが違う定義を書いていた。

食い違いは机上の話に留まらない。`npm run check:stale` は 365 日を超えたエントリを検出して再照合を促す仕組みで、その手順書き(`scripts/check-stale.ts` の出力)は明示的に「**変更がなければ** `lastVerified` を今日の日付に更新」と指示する。CONTENT_GUIDELINES の定義(内容更新時のみ)に従うと、この rolling 更新は禁止されていることになり、陳腐化検知そのものが回らなくなる。

さらに読者に見える面でも問題があった。`lastVerified !== date` のとき、戦略ページとコラムはヘッダーに「**最終更新 YYYY-MM-DD**」と表示していた。照合日の意味で運用する以上、**本文が 1 文字も変わっていない再照合でも日付が動く**。読者には「更新された」と伝わるが、実際には何も変わっていない。エビデンスを扱うサイトで、これは書いていない主張をしていることになる。

## 検討した選択肢

### A. 「一次ソースとの最終照合日」を正とし、CONTENT_GUIDELINES と表示ラベルの両方を直す(採用)

多数派の定義に寄せ、かつ読者への表示を実態に合わせる。

### B. 「照合日」を正とするが、表示ラベル「最終更新」は据え置く

文書の矛盾は消えるが、読者への不正確な表示が残る。コード変更が要らない点だけが利点。

### C. 「実質的な内容更新日」を正とする

CONTENT_GUIDELINES を正とし、`check-stale.ts` と `source-sync-protocol.md` の rolling 運用を作り直す。だが 365 日閾値の陳腐化検知は「一次ソースを見直したのはいつか」を測るためのもので、内容更新日では代替できない。検知の目的自体を再設計する必要が出る。

## 決定

**A を採る。**

1. `lastVerified` の定義を「一次ソースとの最終照合日」に統一し、`CONTENT_GUIDELINES.md` の「lastVerified の運用」節を書き換える
2. 表示ラベルを変更する
   - 戦略ページ: `最終更新 YYYY-MM-DD` → **`最終確認 YYYY-MM-DD`**
   - コラム: `最終更新: YYYY年M月D日` → **`出典の最終確認: YYYY年M月D日`**
3. `CONTEXT.md` / `source-sync-protocol.md` / `check-stale.ts` は既にこの定義に沿っているので変更しない

コラムだけ「出典の」を付けたのは、戦略ページは `Strategy — 最終確認 …` という kicker の文脈で「何の確認か」が読み取れるのに対し、コラムは公開日と並ぶ日付列に単独で出るため、主語がないと本文の確認と読めてしまうことによる。

## 帰結

- **陳腐化検知が意図どおり回る。** 再照合だけの rolling 更新が正式に許可され、`check:stale` の手順書きと執筆ガイドが一致する
- **読者への表示が実態と一致する。** 内容が変わっていない照合を「更新」と呼ばなくなる
- `lastVerified` を持つ既存コンテンツの値は**変更しない**。意味の解釈が変わるだけで、記録されている日付はいずれも一次ソース照合時に打たれたもの
- 表示文言が変わるが、`e2e/` `vrt/` `scripts/` に「最終更新」を前提としたアサーションは無いため、テストの追随は不要
- **VRT は起動し、対象ページも撮っているが、この変更は検出しない。** `vrt.yml` の `paths` には `src/pages/**` が含まれており(ADR 0024 の穴を #433〜#435 で塞いだ結果)、`vrt/pages.spec.ts` は `/strategies/ai-in-education` と `/columns/active-deep-learning-evidence` の両方を撮っている。それでも pass するのは、**短いラベル文字列の差分がフルページ比の 1% (`maxDiffPixelRatio: 0.01`) に届かない**ため。VRT は「レイアウトが崩れていないこと」の保証であって、「文言が意図どおりであること」の保証ではない。文言の確認はローカル目視で行う

## 撤回 / 再検討の条件

- 「本文をいつ書き換えたか」を読者に示す必要が出た場合。その時は `lastVerified` を流用せず、別フィールド(例: `lastEdited`)を立てる。1 つのフィールドに 2 つの意味を持たせたことが本件の原因なので、同じ轍は踏まない
- 陳腐化検知を内容更新ベースに作り替える判断をした場合(選択肢 C への回帰)
