# 0041. 照合日(`lastVerified`)を公開日・更新日として使わない

- 状態: 採用
- 日付: 2026-09-27
- 関連 PR: #(本 ADR と同一 PR で確定)

## 背景

`lastVerified` は ADR 0033 と #678 で「ページの出典との最終照合日」と定めた。照合しても本文が変わるとは限らず、食い違いを見つけてもその PR で直さない照合では日付を進めない(`docs/CONTENT_GUIDELINES.md`「lastVerified の運用」)。

それなのに、この値を次の用途にも使っていた。ADR 0040 は、このうち表示ラベルの外にある 3 点を対象外として #679 に回した。

- コラム一覧とトップの並び順と日付、「(更新)」表示。`lastVerified` が公開日 `date` より前のコラムが 2 件あり、公開日より前の日付に「(更新)」が付いていた
- RSS の並び順と `pubDate`。照合しただけで、記事がフィードの新着として再浮上する
- JSON-LD の `dateModified`(戦略は `datePublished` も。戦略には公開日のフィールドが無い)
- 戦略の OG 画像の `?v=`(ADR 0019)。「OG に出る値を変えたら `lastVerified` も進める」ことを前提にしていたが、今の規則ではその前提が成り立たない

## 検討した選択肢

- **A. 本文の更新日のフィールド(`lastEdited` など)を新しく立て、上の用途をそれに寄せる**。ADR 0033 が再検討の条件として挙げた形。手で更新するフィールドは付け忘れやすい。付け忘れても、どの検査にも引っかからない
- **B. 新しいフィールドは立てない。並び・RSS・JSON-LD は公開日に寄せ、OG の `?v=` は描く内容から作る(採用)**
- C. 据え置く。公開日より前の「(更新)」と、照合だけでの RSS の再浮上が残る

OG の `?v=` については、ADR 0019 が撤回の条件に挙げた「専用の `ogVersion` フィールド」も検討した。これも手で更新するフィールドなので、A と同じ理由で採らない。

## 決定

- コラム一覧・トップの新着 3 件・RSS は、公開日 `date` の降順で並べ、日付も `date` を出す。「(更新)」は出さない。トップの見出しは「最新の更新」から「新着コラム」に改める
- RSS の `pubDate` は `date`
- JSON-LD: コラムは `datePublished: date` だけを出す(`dateModified` は出さない)。戦略は日付を出さない。Google の Article の構造化データに必須のプロパティは無い
- OG の `?v=`: satori に渡す要素ツリー(`src/lib/og-image.ts` の `buildOgElement`)を sha256 した先頭 8 桁。画像と `?v=` は同じ `ogParamsOf` を通るので、描く値と版の元の値の集合はずれない。値・レイアウト・色(`global.css` のトークンから解決した値)のどれを変えても `?v=` が変わり、手順は要らない
- 表示ラベル「出典の最終確認」(ADR 0040)と引用文の日付は、照合日の意味で使っているので変えない

## 帰結

- 本文を改訂したコラムも、一覧・トップ・RSS の上位には上がらない。例として、finland-education-myth は 2026-09-25 に PISA 2025 の結果を追記した(`lastVerified` も同じ日)。変更前は一覧の 1 位で、変更後は公開日の位置(31 本中 27 位)に戻る。本文の改訂を読者に伝える経路は、変更履歴(`/changelog`)に一本化する
- 導入時に、全戦略の `og:image` の URL が 1 回だけ変わる
- フォントファイルと satori の版だけを変えた場合、`?v=` は変わらない。本番の `/og/*` は `max-age=604800`(`public/_headers`)なので、古い画像は最大 7 日と `stale-while-revalidate` の分だけ残る。`og/[...slug].png.ts` の `immutable` は静的出力では効いていない

ADR は不変とする運用なので、旧 ADR は書き換えずに本 ADR で訂正する(ADR 0040 と同じ形)。

## 撤回 / 再検討の条件

- 本文の改訂を、一覧・トップ・RSS でも読者に伝える必要が出た場合。そのときは ADR 0033 が挙げる別のフィールド(`lastEdited` など)を立てる。付け忘れを検査で捕まえる手段も、あわせて設計する
- 戦略に公開日のフィールドを持たせた場合(JSON-LD の `datePublished` を戻す)
- フォントや satori の更新で、古い OG 画像が残ったことが実際に問題になった場合(ハッシュの材料にフォントファイルを加える)
